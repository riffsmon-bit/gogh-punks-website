## Evidence and status rules

- **COMPLETE** means the stated bounded implementation and its relevant acceptance evidence exist. It does not imply every provider, wallet, browser or production configuration is verified.
- **PARTIAL** means useful implementation exists but a requested behavior, integration or acceptance proof remains missing.
- **BROKEN** means an observed user journey or a concrete source path contradicts the exposed behavior.
- **NOT IMPLEMENTED** means no accepted implementation for the requested capability was found.
- **UNVERIFIED** means source/configuration/tests cannot establish the requested live fact.

This audit reuses the [repository map](../v2-swarm/repository-map.md), [shared contracts](../v2-swarm/shared-contracts.md), specialist reviews and [validation ledger](../v2-swarm/validation-results.json), and inspects the owning modules listed below. Historical findings are not copied as current defects when later evidence closes them. The older map, launch matrix, source audit and validation ledger still contain historical archive-blocked statements. The later [archive acceptance](../v2-swarm/free-rpc-production-acceptance.json) and [paid delivery/reconciliation evidence](../v2-swarm/paid-mint-delivery-1599.json) supersede those statements.

The latest recorded integrated checks passed **2,198 JavaScript tests and 140 overlapping deployment checks**. The retained contract run passed **284 tests**. These counts are not additive feature coverage. The compiler gate checks selected domain consumers; it is not whole-repository JavaScript typechecking. Mock wallet/UI results, disposable PostgreSQL/fork results and production receipts are different kinds of evidence.

## Credentials and live proof still needed

Do not request or print secret values. Check presence, scope, model access and a bounded authenticated response separately.

- Archive access is **resolved for the selected tested window**: `ROBINHOOD_ARCHIVE_RPC_URL` and `ROBINHOOD_ARCHIVE_SECONDARY_RPC_URL` were configured for Functions/Production and verified by the scheduled worker. A result at one time/window is not an SLA or proof every historical block is supported. No new RPC account is required just to repeat this audit.
- AI needs actual configured `GOGH_*_MODEL` entries and usable provider credentials or a supported managed gateway binding at runtime. The lead's environment-settings read found `GOGH_GEMINI_MODEL` and no individually stored provider keys; that does **not** prove Gemini credentials are missing because Netlify can inject managed AI Gateway variables. The public `/api/v2/providers` currently reports only Gemini CONFIGURED, not authenticated health. Gemini handles a gateway-bound endpoint; OpenAI/Anthropic gateway base-URL compatibility still needs inspection and a reviewed provider-specific allowlist. `GOGH_V2_AI_CHECK_TOKEN` protects the existing fixed probe. Test intended launch providers with isolated bounded probes before requesting new accounts or subscriptions.
- `OPENSEA_API_KEY` supports current marketplace/portfolio paths; earlier successful reads do not establish all routes or current quota. Original-Punk artwork now has a prepared keyless on-chain path.
- Data acceptance needs deployment schema/role evidence for the actual Netlify/Neon and Supabase connection roles, plus certificate/runtime packaging. Existing disposable role tests are useful but are not a live grant audit.
- Burn asset/obligation coverage remains distinct from a zero ETH balance and from mocked source clearance. General ERC20/NFT/off-chain obligations are not certified by the Forge contracts or by the collection UI.
