# Shared V2 contracts

This is a compatibility contract for the implementation already in this repository, audited against `eec456222bc8028df1f91b3191ce0ff8874c467e`. Art Broker V2 uses `broker/src/v4` internally. Do not create a parallel product version or rename existing stored schemas to match that directory name.

`broker/src/v4/domain/index.mjs` is the shared **server-only** import surface. It directly re-exports existing normalizers, validators and interfaces; no wrapper loosens their behavior. `domain/types.mjs` provides JSDoc contracts and derives result types from the owning functions where possible. This does not switch any production route or worker onto a new implementation. Browser code keeps its browser-safe modules and established authenticated API responses; importing the server facade would pull in Node crypto and viem.

## Identity and authority

The stable original-Punk identity is `{ chainId: 4663, collection: "0xe0f92b3b0e6ded3654177fe3809cd300e5ffadf6", tokenId: "93" }`. Owner, account address, strategy revision and session/ownership epoch are not part of this identity. `normalizePunkIdentity` accepts canonical decimal token-ID strings from `"0"` to `"9999"`, validates the exact chain/collection and rejects extra fields, coercions and accessors. This is syntactic validation, not proof that a token exists. Checksum collection addresses normalize to lowercase. `PUNK_IDENTITY_JSON_SCHEMA` describes the canonical normalized shape; it does not replace `ownerOf` or supply checks. `punkIdentityKey` reuses the existing `assetKey` encoding (`4663:collection:tokenId`) and existing database keys.

`OwnerAuthority` is the existing current on-chain read result, never a reusable permission. `readV2PunkAuthority(tokenId, { expectedOwner, client, registry })` in `netlify/functions/_shared/v2-ownership.mjs` reads original `ownerOf` and the reviewed V3 registry at one block, checks activation/code agreement and rejects a changed expected owner. It returns `chainId, collection, tokenId, owner, punkWallet, activated, blockNumber, nativeBalanceWei`. `readV2ChatAuthority` adds `blockHash`; `assertV2ChatAuthorityUnchanged` checks canonical blocks and transfer history, including transfer away and back. Long-running work must keep its existing continuity/session guards and refresh before delivering protected results or executing.

New composition guards:

| Export | Inputs | Guarantee and boundary |
|---|---|---|
| `assertPunkAuthorityBinding` | Existing original authority snapshot; `{ identity, owner, punkWallet }` selection | Rejects cross-chain/collection/token, owner or wallet mismatches and invalid snapshot fields. Returns no authority. Caller still supplies a fresh authenticated reader result. Wrapped epoch authority is rejected here. |
| `assertPunkCapabilityBinding` | Existing resolver result; its progression snapshot | Requires the same token, owner, block hash and optional epoch, `walletAuthority: "NONE"`, and `requiresSeparateEconomicAuthorization: true`. Does not authenticate the result, validate package eligibility, reread the chain or replace the resolver. Never accept a client/LLM-supplied context through this guard. |

Both guards return `undefined` on success and throw on mismatch. They do not grant a signing token. Chain freshness and canonical-block evidence must come from the owning reader, not timestamps or authority strings sent by a browser. A binding check against two fabricated matching objects proves nothing about the chain.

The separate wrapped-epoch implementation remains in `skill-forge/epoch-ownership.mjs` and Agent epoch modules. It requires pinned wrapper/epoch contracts. Do not substitute wrapper receipt ownership for original owner authority or activate it by attaching an `authorityEpoch` string to an original snapshot. Skills/progression persist by token identity; economic authorizations and active automation do not carry to a new owner. Transfer handling remains the wallet/execution subsystem's responsibility.

## Strategy and execution contracts

`PunkCollectingIntent` contains `schema, version, chainId, punkTokenId, expectedOwner, punkWallet, operatingMode, mintMode, maxMintPriceWei, maxGasPerMintWei, dailyMintLimit, totalMintLimit, minimumReserveWei, maximumCollectionSupply, preferences, requiresWebsite, requiresSocial, preferredSocialPlatforms, blockedContracts, allowedContracts, blockedCollections, allowedAdapters, riskThreshold, requireSimulation, expiration, userSubmittedLinksAllowed, discoveryEnabled`; optional `onlinePresenceRequirement` has the single supported value `WEBSITE_OR_SOCIAL`. Prefer/avoid styles and address lists use the existing validator. Amounts are decimal wei strings; timestamps are ISO strings. Do not convert wei to floating point.

The existing intent schema omits collection because it is already scoped to the canonical collection. An ingress carrying a full identity must validate that scope before applying the intent's `punkTokenId`. Do not add collection or new skill fields into the intent ad hoc: its exact-field normalizer, hash and persisted authorizations would change. Skill gating composes alongside the intent through `EffectiveCapabilities`.

The existing generic executor prepares ASK/ASSIST results and explicitly blocks broad AUTONOMOUS production execution. Its identity includes chain, Punk Wallet, opportunity ID, strategy hash, account nonce and operating mode. Existing Agent Account and selected paid-mint workers are distinct reviewed execution lanes with their own owner/session, runtime, archive, simulation and durable reservation guards; the facade grants no authority to either lane. Do not transplant state names, stored raw transactions or hashes between their journals.

`SecurityScreenResult` and `SimulationResult` are evaluated summaries, not independent proof objects. The executor/security specialist must preserve the binding between the exact adapter-built envelope, chain, wallet, current owner, opportunity, pinned code and simulation block through the existing call path. Do not reconstruct trusted inspection facts from an LLM response or cached opportunity's status flags. No new universal simulation proof schema is claimed in this change.

## Registry, skills and capabilities

The registry ABI definition fields are `manifestHash: bytes32`, `instructionHash: bytes32`, `prerequisite: bytes32`, `capabilities: uint256`, `skillId: uint32`, `version: uint16`, `riskTier: uint8`, `status: uint8`, `disabled: bool`, `deprecated: bool`, `replacement: bytes32`, `reviewEvidenceHash: bytes32`. Viem returns the uint256 capability mask as bigint and small integer fields as number. Numeric status 4 is READY. `skillKey(skillId, version)` remains the canonical on-chain key; string conversational `skill_...` IDs cannot substitute for it.

Reviewed server packages supply `{ manifest, instructions, status: "READY", approved: true }`. `createProgressionReader` configuration comes from the reviewed deployment and pinned code hashes, never a request or an AI argument. The canonical capability names/masks are exported as `SKILL_CAPABILITIES`: CONTRACT_READ, FREE_MINT, MARKET_READ, RARITY_READ, LINK_REVIEW, SCHEDULED_MISSION, ART_CLASSIFY, SOCIAL_READ and PAID_MINT. PAID_MINT currently maps to no MCP execution tools. Presence of a roadmap skill or market data does not make floor buying or WETH bidding executable.

The resolver result is `{ tokenId, owner, blockHash, authorityEpoch?, effectiveProtocolCapabilities, effectiveMcpTools, instructionPackages, walletAuthority: "NONE", requiresSeparateEconomicAuthorization: true }`. Each instruction package carries key, learned level, instructions and manifest/instruction hashes. Tool names are intersected with approved available implementations. `createSkillToolGate({ readState, packages, implementations })` exposes `resolve({ tokenId, owner })` and `call({ tokenId, owner, name, arguments })`. Its call path resolves again after slow research so transfer, unequip or disable cannot leave a stale authorized result. MCP and AI must consume the same gate; neither may infer authority from a skill's title.

Training credits, learned state and equipped state follow the token. Review/learn/equip/unlock/burn transactions remain owned by existing Forge coordinators and contracts, with their current schemas, confirmed receipts and owner review steps. The shared model does not enable training or burns, deploy a registry or change supply/slot rules. Unknown progression is not zero credits or an empty loadout.

## Opportunity, activity and provider interfaces

Normalized opportunities retain the existing source URLs, collection/mint contracts, adapter and code hashes, mint stage/method, price/estimated gas, supply/wallet limits, time window, website/social/image metadata, art styles, screening/simulation/risk fields, expected receiver, unexpected-asset-effect flags, timestamps and dedupe identity. Shared discovery stores receiver-independent candidates where supported; the selected recipient must be resolved for each Punk and checked by policy/execution without starting a separate scanner or poisoning the shared candidate with another Punk's wallet. Normalization is not a general-purpose safe fetcher; link scanning retains its own host/redirect/network boundary.

Activity is descriptive. A wallet request, prepared review, signed transaction, submitted transaction and verified receipt are distinct facts. Producers retain stable IDs and provenance; a merged feed or heartbeat does not prove delivery, refund or finality. Keep raw transactions, private session material, provider secrets and private API responses out of `detail`.

`AIProvider.invoke(task, input)` accepts a bounded prompt/instructions plus optional strict object JSON Schema and output-token limit. Supported task names are the existing `ART_BROKER_AI_TASKS`. Current provider results are `{ provider, modelId, task, text, value, requestId, usage, latencyMs }`; `value` is parsed structured output or null, usage has nullable `inputTokens, outputTokens, cachedInputTokens`. The router/model registry own fallback and cost behavior; unknown usage is not zero cost. Current `healthCheck()` implementations report credential configuration, not an authenticated live call. OpenAI, Anthropic, xAI, Bankr and Gemini are existing adapters, not all proven production-enabled providers.

Model output is a draft or explanation. It must pass existing intent/schema validation and deterministic tool/policy/owner gates. Do not expose unrestricted wallet tools, arbitrary calldata or signing through the provider-neutral interface. Future providers implement the same base-class contract and result format; introducing a dependency does not grant approval to install an external agent skill.

## Integration and validation

Existing imports remain valid. New server work may use the facade while specialists continue to own their original modules. Changes to a shared stored schema, authority model, registry ABI, transaction envelope or execution state machine require an agreed compatibility change before dependent branches implement it. A local type alias alone is not such a migration.

At the initial architecture handoff, the repository had no TypeScript compiler gate. That contribution used JSDoc derived from authoritative JS APIs, `node --check` for syntax and `node --test tests/v2-swarm-domain.test.mjs` for runtime contract validation. The later integrated compiler gate is described below. Tests cover canonical identity/storage compatibility, invalid identities and accessors, owner/wallet/token mismatches, block/epoch result binding, no wallet authority from capabilities, freshness/owner rejection in the existing resolver, unchanged strict intent/skill validators and simulation/execution boundaries. The lead runs the integrated repository, contract, database and browser gates separately.

The integrated swarm adds `npm run typecheck:v2-domain` (TypeScript 5.9.3), required by both site build gates. It compiles strict positive/negative consumers of these authoritative JSDoc contracts. Legacy JavaScript bodies and third-party declaration files remain outside that scoped gate; see [integration-validation.md](integration-validation.md). Runtime validation remains mandatory.
